# Pi 容量与重试核验（2026-10-28）

## 确认的问题与修复

Pi 原来的比例判断按总窗口计算，但另一路容量保护扣除了模型的完整输出预留。500K 窗口配置 128K 输出时，这一路会在约 362K 触发，可能提前装入已经准备好的摘要。接管现在在最终供应商请求上限制输出，给配置的替换点和安全余量留出空间，模型定义保持原样。500K / 80% 时，128K 的实际请求上限为 90K，350K 准备、400K 替换。关闭接管后不再改写输出字段。

最终请求仍核算工具、图片、系统提示和实际输出额度。遇到多个输出字段时检查全部字段、按最大值预留并分别限制，不能通过混用字段绕开保护。99% 等高比例也不会被固定的 90% 保护线提前替换。超大新输入或工具可以触发保护；不可压缩的内容不够放时保留原文并暂停请求。

原重试只设置冷却时间，依赖下一次前台事件。主模型分支现在独立重试，每次最多十分钟，退避从一分钟起、最长五分钟；总时长和次数不设上限。容量等待不再给整项主模型任务另设三分钟总截止。独立 API 高级模式仍保留原有等待机制。

每个任务固定一份原始请求，重试不会换成后来捕获的请求。模型、端点、思考设置和快照均参与核对；模型不匹配或前缀不兼容时等待新捕获。晚启动的后台分支按剩余空间缩小摘要输出，不缩短原始消息前缀。转换、归档和模型请求都在单次截止时间内，迟到结果提交前再次检查取消与来源。

用户停止、会话切换、模型或设置变更、原文失效和关闭扩展会结束旧任务。容量保护引起的暂停保留后台重试；新一轮用户停止仍能取消。替换只读取经过核验的已完成摘要，保留边界之后的原文。
