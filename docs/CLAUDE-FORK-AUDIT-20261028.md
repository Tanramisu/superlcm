# Claude Code 与 Codex 后台分支核验（2026-10-28）

## 确认的问题与修复

原来共用的后台分支实现把提示词中的篇幅估算目标当成整棵摘要树的保存上限。正常结束、结构完整且来源有效的响应，只因略超估算就被丢弃。现在估算只指导模型分配篇幅。原生进程的完整结束回执与独立的返回大小限制仍有效，分块顺序、语言、层级和原文摘要值继续严格核验。

保存摘要与替换上下文分别核验。替换仍按当前上下文、完整摘要包和保留原文计算容量。额外复现了旧打包逻辑跳过放不下的摘要块，却继续声明覆盖对应原文的问题。现在任何必需块放不下，整包都不能用于替换，交回 Claude 原生压缩；已经保存的摘要和原文保留。

原生后台分支每次尝试默认最多十分钟。真正的完成回执到达后立即接收，不等待进程退出。生产摘要工作进程在失败后自行等待再试，等待从三十秒递增，最长五分钟，没有整体时限和次数上限。旧的三次失败记录不再永久阻止原生分支排队；缺少可执行程序则直接报告。

重试保留原文计划和单一任务归属。无效格式重试只在摘要指令末尾追加纠正提示。保存失败时保留已经核验的响应，重试保存，不重新调用模型。配置、归属、原文摘要值变化或显式取消后停止旧任务，超时后的迟到响应不能保存。后台记录失败次数、等待时间和经过过滤的错误类型，不保存上游错误中的凭证或任意原文。
