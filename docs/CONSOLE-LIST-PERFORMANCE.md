# 后台列表卡住的修复

打开后台时，页面先显示框架，对话列表和接入状态一直不出现。根因是列表请求对分页内的会话计算完整摘要工作量，又为全局“需要关注”计数枚举会话并再次计算。工作量计算会验证并读取历史原文，在大归档上长时间占用后台线程，阻塞其他请求。

列表页现在从已保存的任务状态、失败记录和设置读取状态。未执行详细估算的已配置会话显示“后台摘要已配置”，不会把未核实的摘要覆盖误报为完成。全局计数直接查询索引，分页外会话不会被读取原文。打开单个会话和明确生成预览时，仍使用原有详细估算。

永久回归覆盖：列表状态不读取原文，失败和运行状态仍准确；分页、跨页全局计数、需要关注和无交互任务筛选均正常。相关四组回归共 54 项通过，185 个源码文件语法检查通过。

本机归档实测包含 877 个会话、约 113 万条记录。修前列表请求超过 12 秒仍未返回，后台持续占满单核。修后首次列表请求约 0.48 秒，后续分页约 0.13 秒。远程 HTTPS 的关注列表约 0.76 秒，无交互任务列表约 0.04 秒。真实 Chrome 刷新后确认列表、摘要详情和已接入状态显示完整。上述数字是本轮观察值。

本轮只更新后台列表读取方式，保留原文、摘要和模型设置。
