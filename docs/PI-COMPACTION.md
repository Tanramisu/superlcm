# Pi 后台摘要与直接替换

SuperLCM 默认沿用主模型及账号，在后台分支一次写出分块、上层摘要与根节点，主会话继续工作。独立 API 模型作为高级选项保留。上下文到80%时，只读取、校验并装入已经完成的摘要，不发起新的摘要模型请求。

## 实际流程

1. 达到约70%后，扩展从 Pi 正式提供的模型可见记录里选取可压缩的旧前缀，在后台保留原请求前缀、追加整树摘要指令。最近对话按 Pi 的 `keepRecentTokens` 保留。长工具链可以在已闭合的工具组之间选边界，当前完整用户请求另外原样保留。
2. 后台准备期间，模型和工具照常执行。完成结果保存在 SuperLCM 数据库。后来追加的消息留在原文尾部，不会使已完成前缀失效。
3. 达到80%时，扩展在 `turn_end` 的正式边界条目接口返回一个压缩条目，Pi 自己保存并重建模型上下文，原工具链接着执行。此过程不调用 `ctx.compact` 中断正在执行的任务，也不再次生成摘要。
4. 空闲会话和手动压缩通过 Pi 的 `session_before_compact` 接口读取同样的已完成结果。该接口只有查询和安装，没有摘要生成路径。

如果生成还没完成，继续保留原文，不在80%的入口临时发起摘要生成。后台失败可以在冷却后重试。切换模型、修改旧消息、换分支或更改摘要配置时，不复用失效的摘要。普通追加不作失效处理。

## 容量保护

正常情况下70%准备、80%替换。另设容量保护：系统提示、工具定义、最近原文、新输入、图片和模型输出预留都计入预算。输出预留较大时可以提前准备和替换，避免必须等到70%才能恢复。

接近安全上限而摘要仍未完成时，暂停下一次模型请求，等待已经启动的后台工作。旧摘要覆盖不足时最多重新准备一次。摘要失败或最近工具结果本身过大时，中止本轮并保留原文。发送前还对实际完整消息复核，调用 Pi 的中止信号阻止供应商发出请求。被拦住的新输入保存在原生会话的 `superlcm-deferred-input` 条目中，需要恢复后重新提交，界面会明确提示。

这些预算使用文本估算，图片单独预留空间，不把图片的base64编码当文字。最终准确用量由供应商报告。

## 配置

本地后台打开 `http://127.0.0.1:8791/#connect`，在 Pi 卡片选择“主模型后台分支”。关闭压缩接管仍会独立保存后台摘要；需要替换上下文时，再展开“可选压缩接管 → Pi”启用，默认80%。

```sh
node src/cli.js setup pi --apply
node src/cli.js pi-policy --enable --summary-mode main-fork --ratio 0.8
node src/cli.js pi-policy
```

高级独立 API 模式可显式传入 `--summary-mode api --api-ref <已保存模型编号>`。关闭接管不会删除摘要方式。主模型分支不需要独立模型凭据；配置有误时不自动改用 API。

主请求从 Pi 公开的 `context_with_system` 和 `before_provider_request` 接口捕获。分支通过同一个模型注册表发送，保留请求设置、工具和缓存控制；后台不会执行工具。替换入口 `pi-ready` 与 `session_before_compact` 只有查询和安装路径。

## 验证范围

`npm run test:pi` 检查来源映射、工具闭合、失效、容量保护和事务。`node scripts/verify-pi-compaction.mjs --main-fork` 使用本机 Pi SDK 和本地假供应商，验证70%后台准备、主工具链继续、80%原生边界替换、零替换阶段摘要请求，以及新增用户和工具原文保留。此项已在 Pi 1.4.0 验证，不代表实际供应商缓存命中率；用量回执才是缓存证据。
