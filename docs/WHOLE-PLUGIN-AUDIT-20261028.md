## 真实 DSH 摘要超时故障

一段实际 DSH 会话的三次分支请求各在约 600 秒被客户端取消。供应商服务记录显示三次请求都在接近取消时仍收到输出，因此硬截止会丢掉仍在生成的摘要；仅重复同样请求不保证恢复。本次被取消的请求没有最终用量回执，不能据此声称缓存命中或摘要完整。

用户同意将单次十分钟改为无有效进展的超时。DSH 主模型分支仅在收到非空白文本或推理增量时刷新计时；空白、状态消息和用量消息不刷新。连续十分钟无有效输出仍取消该次请求并沿用原有无限重试，用户取消、设置变更、来源改变和流结束校验仍生效。主请求必须等到完整且通过校验的摘要才能替换，原文和当前请求继续保留。

Pi 主模型分支也有同类硬截止，且原来存在内外三层计时。现通过本机 Pi 公开流式事件，将有效文本和推理增量传递给各层计时器；准备阶段卡住、空白增量、未完成流和用户取消仍会按原保护处理。Pi 的修复尚未安装到正在使用的扩展。

目标 T3 DSH 配置已使用原已安装包的最小补丁快照；运行中的旧进程需要重启才会加载。该快照不包含本页其他尚待复审的全插件改动，其他 DSH 配置尚未更新。已在独立副本测试持续输出超过十分钟、空白心跳、连续超时、迟到结果及用户/设置/模型/来源/销毁取消；真实会话是否最终替换以其后续回执为准。

补充两项防护：摘要聚合会传播来源不完整的旧质量标记；DSH 新版状态记录保留最近失败类型，下一次重试开始时不再丢失诊断。失败记录只保存错误分类和时间，不保存用户内容或供应商错误正文。

## 仍需明确的边界

原文磁盘归档完整，不等于每次模型请求一定完整；接管只使用经过覆盖和容量核验的结果。不完整来源只作导航，容量不足时保留原文并暂停或交回原生宿主。32 MiB 以上的单条 DSH 记录仍受明确安全上限约束。全量原文搜索需要按返回游标完成扫描，不能把部分无匹配当成全库无匹配。

本机缺少 Claude CLI，真实 Claude SDK 接管尚未运行；相关测试是生产函数和合成宿主数据。Codex 的后台分支已按本地协议测试，但其原生压缩仍由 Codex 负责。Windows 接入、全部第三方扩展组合、真实网络故障及供应商缓存计费仍有验证缺口。新接入和旧客户端重载是不同状态，安装回执不能证明已经运行的会话加载了新代码。
