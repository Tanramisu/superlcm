# DSH 后台分支重试核验（2026-10-28）

修复原来第一次后台摘要失败后只设置冷却、必须等前台再次请求才会重新尝试的问题。DSH 接管的主模型分支现在冻结原始请求和来源范围，每次尝试单独限时，失败后后台递增等待再试。默认每次 10 分钟，等待最长 5 分钟，整个任务没有总时长或次数上限。

## 提交与取消边界

- 达到容量保护线的请求保留并暂停，不向供应商发送超预算的前台请求。核验通过并替换后，由真实 DSH 宿主重新组装同一个请求。
- 无效 JSON、缺失层级、工具调用、不完整或超额摘要都不能提交。格式错误后的重试只在末尾摘要指令增加纠正提示，原始请求前缀不变。
- 用户停止、设置或模型变化、原文范围被替换、引擎退役会取消旧任务。每次重试前后核验代次、策略和原文，迟到的响应不能复活旧替换。
- 已取消任务不再给新配置登记一次失败冷却。旧 API 模式的容量等待规则保持原有截止时间。
- 状态仅保存尝试数、失败次数、下一次尝试时间和安全错误分类。活动摘要优先于大量归档扫描回执，兼容没有重试表的旧数据库。

- 相关控制台、页面、安装及比例配置 66 项通过；新增控制台状态回归单独复跑 10 项通过。
- 239 个文件语法检查通过，`git diff --check` 通过。
- 新增 7 项重试测试。虚拟推进五次十分钟超时，再注入供应商额度错误及损坏 JSON，第八次成功；当前请求始终保留、只替换一次、旧尝试晚到时不再替换。另测空闲后台自动重试及用户停止、配置、模型、来源变化和退役取消。

全仓普通测试为 574 项，540 项通过、34 项失败。未修改的基线 `ba5835b` 独立快照为 573 项，539 项通过、34 项失败，失败名称集合完全相同，集中在 Claude 补救与旧宿主摘要测试。本次新增控制台用例通过，未新增全仓失败。

离线响应验证调度、取消和提交边界。真实供应商持续报错时，任务会继续等待并重试，不能承诺下一次尝试必定成功。
