# 后台分支、容量保护与替换故障审查

日期：2026-10-24。

## 结论

本轮由当前主会话逐段检查实现并执行离线故障注入，未委派独立审查。发现并修复 Pi 的实际缺口，再通过真实安装的 Pi SDK 和两版 dsh 的真实宿主验证关键发送、等待和替换行为。模型供应商均为本地测试接口，没有调用付费模型。

当前状态为**警告**：本轮相关测试通过，主仓库完整测试仍有改动前已存在的失败。不能将专项通过写成整库验收通过。完整数字及其范围见文末。

## 本轮确认与修复

- **不响应取消的供应商**：旧 Pi 分支只把取消信号传给供应商，如果供应商忽略信号，等待不会结束。新实现独立限制等待时间，拒收晚到输出，并阻止已取消分支再次发送。
- **容量等待没有总时限**：旧代码等待现有任务时没有额外截止时间。新实现给当前任务、最多一次重新准备和结果查询共用一个三分钟时限。空闲替换回调也有截止时间，失败时保留输入并停止本次发送。
- **会话和模型切换**：旧容量等待可能在会话关闭后重新准备；旧查询和替换回调可能清除新任务。现在取消旧会话等待，核对任务归属，旧回调不清除新会话或新模型的草稿。
- **最终请求漏检**：原先只检查模型可见消息，最终请求内另列的超大工具定义和输出上限可能漏过。现在在公开发送钩子检查整个原生请求，包括工具、实际输出预留与图片。后台分支追加指令后的最终请求也重新检查。
- **空结果卡住**：服务返回空准备结果时，旧状态会永久停留在等待。现在将空结果视为失败，释放状态并进入重试等待。读取准备结果时也拒绝空白或缺少标题的摘要。
- **重试等待**：连续失败从一分钟开始逐步延长，最长十六分钟。到期后由下一次输入、工具轮次或会话活动触发，不设置持续购买摘要的后台定时器。模型或配置改变后清除旧配置的等待限制。读取配置失败也不会让失败处理再次抛出未处理异常。
- **关闭接管后的摘要**：归档准备接口错误地要求必须开启压缩接管，导致 Pi 被动后台摘要无法运行。现在独立核对后台摘要开关，关闭接管仍可保存完整树。

## 突然增长时的行为

70%是正常准备点，80%是正常替换点。比例并不是唯一保护条件。系统提示、工具、输出预留、新输入、图片和追加工具结果都参与容量检查，必要时更早准备或暂停。

到80%而摘要未完成时，可以在仍有安全空间的范围内继续保留原文。达到容量保护线后，停止下一次模型发送，等待已经启动的任务。准备完成后，重新计算根摘要、固定提示及全部保留原文是否容得下。旧摘要覆盖不足时至多再准备一次，两次工作共用同一个等待截止时间。

如果本次输入或最新工具结果自身过大，即便换掉旧上下文也放不下，就停止本轮，保留完整原文和输入，提示用户等待或缩短输入。不会为了继续发送而机械截断用户输入或工具结果。

Pi 等待中的新输入在等待开始前写入原生会话条目。恢复成功时继续提交；失败或会话切换时仍有完整记录。正在执行的工具链通过正式轮次边界替换，空闲替换通过宿主压缩接口完成。

## 异常模型回复与重试

格式错误、缺块、顺序错误、超出总预算、截断、工具调用、错误结束、超时及取消均拒绝保存或替换。先检查整棵树，再保存，失败不产生可替换的半棵树。来源、边界、当前模型和设置发生变化时，旧结果失效；正常追加的原文继续保留。

已持久化的完成结果优先查询复用，替换入口只读取现成结果。达到容量保护线后的受限重新准备属于恢复流程，不改变80%普通替换入口只读的规则。原文始终独立保留。

已完成但尚未持久化的模型输出遇到进程退出或保存失败，后续仍可能重新生成；本轮没有验证断电场景下的计费去重。

## 实际宿主故障注入

Pi 使用本机 Pi 1.4.0。测试经过其真实工具循环和本地 HTTP 供应商，覆盖：

- 正常后台生成、连续工具调用、80%替换和近期用户及工具记录保留。
- 慢摘要到达保护线后等待现有工作，替换时不另买摘要。
- 摘要接口失败、无效 JSON、缺少节点以及截断输出。
- 超大新输入和不可缩减的巨大工具结果。
- 原生请求中新增加的超大工具说明，以及实际请求中大于默认值的输出预留。
- 关闭接管时只生成并保存一次完整树，不替换上下文。
- 独立 API 高级模式的正常流程回归。

上述超限及异常响应场景中，不安全的额外主模型 HTTP 请求数均为零，原文保留。另有单元用例测试供应商忽略取消和超时、配置中途不可读、空结果、模型切换、旧查询、旧替换回调与递增重试。

dsh 两版新增同一组九项真实宿主测试，覆盖错误 JSON、缺节点、错顺序、超预算、额度错误、永不结束、超时后晚到结果，以及后台尚未完成时追加可恢复或不可缩减的大输入。可恢复时复用现有分支替换；不可恢复时停止下一次请求，完整输入保留。

## 边界

容量使用估算和供应商报告，依赖宿主提供正确模型容量；这不能保证所有供应商分词和全部第三方扩展组合永不拒绝请求。Pi 原样分支当前需要供应商提供受支持的 `messages` 或 `input` 请求数组，不兼容的格式会拒绝生成并保留原文。

树的格式和来源检查不能证明模型正文没有遗漏或事实错误。当前用户约束及近期原文额外保留，历史关键细节仍需查回完整原文。缓存计数验证了回执传递，未测付费供应商的实际命中率。Claude 本机未安装，本轮没有新增真实 Claude 宿主验证。

Pi 已加载的旧扩展需要重新加载。dsh 的取消接入状态保持原样，离线宿主测试不等于已经为用户重新接入。npm 包未发布。
