# Claude 接管的对话模型兜底

完整 SuperLcm 0.5.30 为 Claude Code 补上对话模型兜底。DSH 独立版的对应能力已在 0.5.32 提供；这次不修改 DSH 压缩引擎。默认接入仍只归档、写后台摘要和提供查询。下面的行为仅在用户明确打开 Claude 压缩接管后发生。

## 何时调用对话模型

正常情况直接组装已完成的分层摘要，替换步骤无需调用模型。少量缺失的后台分块仍可以在有界等待内补齐。若覆盖不足、旧边界无法放置，或替换后仍占太多空间，插件才尝试当前对话模型一次。

与 DSH 的紧急额度兜底不同，Claude 的入口是宿主已经发出的 `session.compact`，包含预先计算压缩。它不要求所有摘要路线先耗尽额度，也不在日常后台写摘要时调用这个最终兜底。主模型调用可能增加等待和用量，上限为 90 秒；不进行质量修正循环。相同失败批次冷却五分钟，期间交回 Claude 原生压缩。子代理继续使用原生压缩。

输入复用已验证的旧摘要，只加入剩余历史的完整原文。当前任务的完整用户请求和最近原文受保护，完整工具调用及其结果留在同一侧。长自主轮次需要单独携带当前请求时，这段请求保留原文，不进入新摘要的生成源。较新的明确指令仍然优先。

必须能唯一对应整段活动会话和归档。比较完整可见文字及工具标识，宿主提供工具参数或输出时也比较这些内容。真实原生摘要必须有原始记录的 `isCompactSummary` 标记，用户引用同样的开头不获得这个身份。重复短提示无法证明当前任务时，拒绝猜测。

## 保存和重试

合格的最终输出先成为持久草稿，再发布摘要根。原有摘要节点和原文均保留，新的根引用旧摘要，并记录精确的原文范围及校验值。成功后正常压缩组装和后台分块能识别这个根已经覆盖的历史。展开树根时，旧摘要和直接读取的原文范围都有独立导航入口。

临时写入失败只重试保存，最多立即尝试两次，不再次调用模型。结果已经存成持久草稿时，重开模块或命令行也能恢复它。尚未进入保存进程的结果保留在模块内存；宿主进程若在第一次持久写入前退出，内存结果无法恢复。永久磁盘故障仍保留失败。

普通后台分块也保留生成结果。保存边界临时失败后，可以用同一结果再次保存；节点已写入而回执丢失时，确认原批次、原领取标识和完整输出后返回原成功回执，不重复生成。

取消、会话结束、模型切换、摘要设置变化及原文源推进会撤销旧生成工作的使用资格。超时或取消后迟到的模型输出不能继续保存。取消标记先写入不依赖数据库锁的私有文件，保存进程取得写锁后再次核对，防止排队中的保存越过取消。标记不含对话原文。已经验证并完成发布的摘要作为历史档案保留。

## 验证范围

永久测试使用正式插件事件、真实 CLI、临时 SQLite 和本地假模型，检查当前输入、工具边界、树引用、原文及旧节点是否一致，并注入额度、质量、取消、超时、设置变化和写入故障。独立审查使用另一套探针复核。发布检查还覆盖完整回归、安装包执行及共享 DSH 核心。

这些检查覆盖故障恢复与数据一致性。真实供应商摘要的语义质量和 Windows/Linux 实机仍需另行验证。GitHub 自动测试保持关闭。
