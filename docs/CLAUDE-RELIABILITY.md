# Claude 接管压缩的验证与边界

Claude 连接默认只归档和生成后台摘要。接管压缩需要在 SuperLcm「压缩」页显式启用。后台开关和模型设置由后续请求读取；插件代码更新需要 Claude 重新加载模块，活动会话不会自动换成新代码。

## 0.5.34 修复

感谢 [muxammadreza](https://github.com/muxammadreza) 提交真实使用问题和工作补丁。本版借鉴 [#14](https://github.com/yu381792/superlcm/issues/14)、[#15](https://github.com/yu381792/superlcm/issues/15)、[#16](https://github.com/yu381792/superlcm/issues/16)，另按真实宿主与来源校验补足保护。

- 模块加载失败：流式回答钩子改为异步生成器，跨文件辅助函数只接普通回调。真实 Claude 会实际加载和调用整个模块图，避免普通 JS 模拟测试通过而宿主拒绝加载。
- 摘要准备落后：通常保持设置的分块粒度。接管压力升高时，可在完整工具结果之后提前关闭尚未满额的尾段。摘要不足的预计算可以延后，到实际压缩时仍走有界准备、最终主模型兜底或 Claude 原生压缩。摘要关闭、缺配置或失败退避时，不把没有可运行任务的状态当作持续准备。
- 任务通知占满保留区：从精确原始记录识别人类提问与系统通知。手动压缩尝试更小的保留区，但只能舍弃已经覆盖的历史，当前授权、工具配对和未覆盖的原生续接内容仍保留。来源不明确时继续保守处理。
- 实际工具字段：核对 Claude 的 `tool`、`text` 字段并兼容旧 `name`、`content`。工具名或结果改变时，不用旧归档授权最终摘要。

完整下级摘要可以替代被截短的父摘要。真正被截短且没有完整替代来源的叶摘要仍只用于查询导航，不能作为完整上下文替换。

## 可重复验证

```sh
npm run test:claude-module
npm run verify:release
```

第一条使用本机实际安装的 Claude `plugin test`，测试 HOME、配置和数据库全部隔离，模型与进程接口由离线服务实现。实际接口调用覆盖加载、流式输出、摘要替换、主模型兜底、失败交还和预计算延后。缺少支持该命令的 Claude 时明确失败。

完整发布检查另包含真实 CLI、临时 SQLite、来源拒绝、工具边界、压力尾段、旧格式和 DSH 回归。独立审查分别核对真实 Claude 模块行为与真实 CLI 数据保存，两层证据各自注明范围。

本轮宿主为 macOS 上的 Claude Code 2.1.293。其他版本、Windows/Linux 实机和付费模型的摘要语义质量需分别验证。测试不会更改用户正在使用的会话、插件缓存或接管开关。
